## Критерий 1. Качество прогноза — до 10 баллов

```
WAPE-score = max(0, 1 − Σ|y − ŷ| / Σy)
```

| WAPE-score | Балл | С весом 2 |
|---|---|---|
| ≤ 0.48 (не лучше baseline) | 0 | 0 |
| 0.48 – 0.60 | 1 | 2 |
| 0.60 – 0.70 | 2 | 4 |
| 0.70 – 0.80 | 3 | 6 |
| 0.80 – 0.88 | 4 | 8 |
| **> 0.88** | **5** | **10** |

**Критерий закрыт на максимум, 10 баллов.** Лучший результат команды на
лидерборде — **0.89447**; в зачёт идёт лучший за всё время, по нему
оценивается критерий. Сданный релиз, который лежит в репозитории и отдаётся
сервисом, — **0.88987** (маршрут 5 нулевой). Он тоже выше 0.88.
Шкала кончилась: дальнейшее улучшение прогноза баллов не приносит. Модель
заморожена.

- [x] Превзойти базлайн 0.48
- [x] Попасть в диапазон 0.80–0.88 (0.86923, статистическая модель)
- [x] Пересечь 0.88 (модель Стаса: лучший прогон 0.89447, сданный релиз 0.88987)

## Критерий 2. Данные, внешние источники, применимость — до 8 баллов

### а) Внешние источники — до 4 баллов

По одному баллу за источник. **Обязательное условие: рабочая ссылка и
подтверждённый эффект.** Источник без ссылки не засчитывается.

| Категория | Статус | Что нужно |
|---|---|---|
| Сезонность и календарь | почти готово | Ссылка на производственный календарь есть, эффект измерен (0.49 в каникулы). Оформить в `factors.py` |
| Погодные условия | не сделано | Архив Open-Meteo за ноябрь–декабрь 2025, признак в модель, замер эффекта |
| Дорожный трафик | не сделано | Найти источник, использовать, показать эффект |
| Прочие факторы (ремонты, события) | наполовину | Детектор закрытий работает, нужна внешняя ссылка на новости о ремонтах |

- [ ] Календарь: ссылка + эффект в `GET /api/factors`
- [ ] Погода: выгрузить, кешировать в репозитории, добавить признак, замерить
- [ ] Трафик: источник + ссылка + эффект
- [ ] Ремонты: ссылка на новости про закрытия маршрутов 7, 17, 50

### б) Область определения и адаптации — до 2 баллов

Команда чётко понимает, на каких маршрутах, горизонтах и диапазонах данных
модель валидна, от каких внешних данных зависит и что нужно для переноса.

- [x] Текст написан (`docs/model.md`, раздел ограничений)
- [x] Отдаётся через `GET /api/scope`
- [ ] Перенести в форму сдачи, поле 4

### в) Корректирующие коэффициенты — до 2 баллов

- [x] API принимает коэффициенты (`k_global`, `k_weather`, `k_event`, `k_routes`)
- [x] Ответ содержит описание применённых поправок
- [ ] **В интерфейсе есть контролы, и прогноз меняется сразу** (+1)
- [x] Корректная агрегация целевой величины
- [x] Воспроизводимый пайплайн приёма данных (+1)

## Критерий 3. Архитектура и производительность — до 5 баллов

- [x] Читаемое разделение на модули: приём и нормализация → признаки и
      геопривязка → прогноз и агрегация → API → фронт
- [x] REST API отдаёт прогноз по параметрам: маршрут, остановка, интервал,
      горизонт
- [ ] **Цифры latency и RPS в README** — обязательно, жюри своего теста не
      проводит, засчитывается честная заявленная оценка
- [ ] **Запускаемый сервис** — без него балл существенно снижается
- [x] Совместимость с горизонтальным масштабированием (stateless, кеш в
      процессе)

Целевые показатели: один контейнер 2–4 vCPU и 2–4 ГБ RAM, сотни RPS,
p95 менее 200–300 мс, CPU 60–80%, RAM стабильна без swap.

При разработке в облаке получилось 2449 RPS при p95 36 мс на 2 vCPU.
**Эти цифры в README идти не должны** — нужен прогон на своей машине
в лимитах `--cpus=2 --memory=2g` и свои числа.

## Критерий 4. Полнота функциональности — до 4 баллов

- [ ] Три горизонта: день обязателен, месяц и год хотя бы качественно
      (API готов, нужен интерфейс)
- [ ] Агрегация по маршруту, остановке или участку, интервалу времени
      (API готов, нужен интерфейс)
- [ ] **Интерактивный дашборд с картой Москвы**
- [ ] Выгрузка в CSV или XLSX (API готов, нужна кнопка)

Оговорка по остановкам: привязки валидаций к остановкам в данных нет,
поэтому разложение оценочное и помечено `estimated: true`. Это честнее,
чем делать вид, что модель работает на уровне остановок.

## Обязательные артефакты на сдачу

Шесть полей формы, все обязательные:

1. Ссылка на артефакты ML-модели, код обучения и инференса, README с запуском
2. Ссылка на все внешние данные (трафик, погода, календарь, новости)
3. Ссылка на запускаемый веб-сервис (Docker/Compose): backend + frontend,
   точки входа API, инструкция для жюри
4. Ссылка на схему архитектуры и модулей, описание области определения
   и адаптации модели, зависимостей от внешних данных
5. Сведения о производительности (замеры, нагрузочный тест) и список
   дополнительных возможностей
6. Описание ограничений решения и плана развития

Детальный чек-лист по каждому полю: `docs/submission.md`.

## Лимиты сдачи

**CSV на лидерборд:** 36 попыток в день всего, 24 успешных (со скором
0 и выше). В зачёт идёт **лучший результат за всё время**, поэтому
отправлять можно смело — ухудшить нельзя.

версия**.
