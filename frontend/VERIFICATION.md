# Проверка реализации

- `npm run build:service`: собирает `dist/` и обновляет `service/static/` для штатного Dockerfile.
- `npm test`: 11 тестов, все прошли при текущей интеграции.
- Edge / Playwright: вход без заполнения полей, показ/скрытие пароля, навигация, три горизонта, выбор маршрута, обновление коэффициента, панель остановок, закрытие по Escape.
- Контракт на перехваченных тестовых HTTP-ответах: относительные `/api`, debounce, совпадение коэффициентов прогноза и ссылки XLSX, `name`, `note`, отсутствие повторного умножения события сети.
- Годовая тепловая карта объединяет историю и прогноз: 12 месяцев.
- Проверены 1280×720 и 390×844: нет горизонтального переполнения страницы. На телефоне плотные графики прокручиваются внутри своих панелей.
- Диспетчерская 1280×720: высота страницы 720 px, карта 398 px; обязательная оговорка по остановкам видна.
- Ошибки JavaScript на проверенных сценариях не обнаружены.

## Первоначальная проверка на моках (история)

При первоначальной проверке живой бэкенд ещё не был предоставлен. Эти ограничения относятся к ранней версии; дальнейшая интеграция описана ниже. Перехваченные ответы не заменяют проверки живого API.

Маршрутная геометрия не выдумывается: без API карта содержит только подложку OpenFreeMap. Операции выпуска/перераспределения вагонов отсутствуют в контракте, поэтому интерфейс не имитирует отправку команд. Спутниковый слой не предоставляется OpenFreeMap, кнопка удалена по просьбе пользователя.

Визуальная реализация — первая версия по растровым макетам. Иконки, шрифты, графики и содержимое динамических панелей не гарантируют пиксельного совпадения. Фон входа очищен от встроенной формы, а интерактивная форма остаётся отдельным HTML-элементом.

В sandbox Codex оптимизатор dev-сервера Vite столкнулся с запретом чтения родительского каталога. Для просмотра запущена готовая production-сборка через `npm run preview -- --port 5173`. Сборка использует `--configLoader runner`, чтобы не зависеть от доступа к родительским каталогам при загрузке конфигурации. Обычный `npm run dev` предназначен для локальной среды разработчика.

## Правки интерфейса

Увеличена надпись в шапке входа, центрирована исходная иконка трамвая. Выбор времени ограничен целыми часами 0–23; при изменении границ сохраняется корректный порядок. Убраны спутник и дублирующие переключатели горизонта. Часы и положение навигации унифицированы. Добавлены подсказки по наведению, фокусу и нажатию; тёмные полосы прокрутки; устранено сжатие блока данных под изображением. Проверки в Edge: 1280, 1024, 768, 390 px, совпадение координат навигации между экранами, отсутствие перекрытия блоков, допустимые часы и упорядоченные границы, доступность подсказок.

## Стыковка с живым бекендом (сентябрь 2026)

Проверено против сервиса в Docker (2 CPU / 2 GiB, два воркера) на
`localhost:8000`, сборка из `service/static/`. Работает: вход без пароля,
карта с линиями пяти маршрутов и списком маршрутов без координат, фильтры
по маршрутам, датам и часам, «День / Месяц / Год» (год — история
январь–октябрь плюс прогноз ноябрь–декабрь), коэффициенты (база, сценарий,
изменение; ползунок −15% → 238 937 → 203 096), XLSX с теми же
коэффициентами (настоящий файл, сумма совпадает с экраном до округления
строк), разбивка по остановкам с оговоркой, добавление и снятие закрытия
через форму администратора, состояния загрузки, пустого ответа и ошибки.
`npm test` — 6 из 6.

Что пришлось поправить под реальные ответы API:

- ответы из кеша бекенда приходят без `Content-Type` — клиент разбирал бы
  их как HTML; теперь отвергается только явная HTML-страница;
- «Состояние данных» и «Данные до» — поля `/api/meta`: `cutoff_date`,
  `data.loaded_at`, `data.forecast_rows`, `model_version`, `release_id`;
- «Точность прогноза» — `score` релиза (1 − WAPE на лидерборде), а не «—»;
- На этапе первой интеграции «Внешние факторы» показывали `/api/factors.sources`.
  В текущем UI эта плашка заменена справочными «Факторами прогноза»;
  измеренные источники и их эффекты там больше не выводятся.
- история для графиков: прогноз начинается после среза, факта на ту же
  дату нет. День — средний профиль того же дня недели за 4 недели до
  среза, месяц — 31 день до среза, год — история по месяцам. Раньше
  запрашивались 2021–2024 годы и история на дату прогноза (400);
- preview на годовом периоде отдаёт дни — сворачиваются в месяцы;
- рейтинг и рекомендации — по объёму, а не по номеру маршрута;
  маршрут с нулём пассажиров в рекомендации не попадает;
- тепловая карта — колонки по ключу периода (у маршрута 5 за год только
  ноябрь и декабрь), подписи из ключа;
- на горизонте «день» выбор даты меняет обе границы; переключение
  горизонта строится от выбранной даты, а не от 1 января;
- XLSX и разбивка по остановкам получают сценарий диспетчерской
  как `k_global` — произведение факторов из `explain` preview;
- подсказка демо-доступа на экране входа; из легенды убран «Диапазон
  прогноза» — интервалов на графике нет.
